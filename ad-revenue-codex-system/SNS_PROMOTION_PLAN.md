# AI Biz Note SNS拡散メモ

目的は、AdSense向けの自然検索だけに頼らず、SNSから記事を読んでもらい、必要な人を相談メニューへ送ることです。

## 優先する媒体

1. X
   - 記事更新、短い気づき、チェックリストを投稿する。
   - 1記事につき3投稿に分ける。

2. Threads
   - Xと同じ内容を少し柔らかい文章で再利用する。
   - 相談につながる実務の悩みを書きやすい。

3. note
   - 週1本、AI Biz Noteの記事を要約して、最後に本記事へリンクする。
   - 「詳しい手順はこちら」として本サイトへ送る。

4. YouTube Shorts / TikTok
   - すぐには必須ではない。
   - 伸びた記事を30秒のチェックリスト動画にする候補として残す。

## 1記事あたりの投稿パターン

### 投稿1: 悩み提示

例:

> 問い合わせ対応をAIで楽にしたいなら、最初に決めるべきなのはツールではなく「どこまでAIに任せるか」です。返信範囲、確認ルール、テンプレートを先に決めると、事故が起きにくくなります。
>
> 続き: 記事URL

### 投稿2: チェックリスト

例:

> AI活用を始める前の確認リスト
> - 目的は一つに絞ったか
> - 使ってはいけない表現を決めたか
> - 人が確認する条件を決めたか
> - 出力形式を固定したか
>
> 詳細: 記事URL

### 投稿3: 相談導線

例:

> 記事を読んでも「自分の事業だと何から直すべきか」が分かりにくいことがあります。AI Biz Noteでは、Web集客、LP改善、AI実装を小さく相談できます。
>
> 相談メニュー: https://aibiz-note.jp/consultation.html

## 今週使う記事

- AIで問い合わせ対応を整えるための返信テンプレート設計入門
- 問い合わせ対応をAIで楽にする前に決めるべきこと
- LPのファーストビューで離脱を減らすための確認ポイント
- Search Consoleで初心者が最初に見るべき三つの数字
- AIで記事構成から本文下書きまで作るときの実務手順

## 投稿前チェック

- 誇張した収益表現にしない。
- 「必ず稼げる」「自動で売れる」などは使わない。
- 記事URLと相談URLを混ぜすぎない。
- 1投稿1テーマにする。
- AdSense審査中は、過度な営業より実務情報を優先する。

## 下書き自動生成

次のファイルをダブルクリックすると、X、Threads、note、投稿前チェックリストの下書きを作れます。

```text
generate-aibiz-social-drafts.cmd
```

出力先:

```text
ad-revenue-codex-system/social-drafts/
```

生成されるもの:

- `YYYY-MM-DD-x-threads.md`: 今日のX/Threads投稿案
- `YYYY-MM-DD-all-article-x.md`: 全記事別のX投稿案
- `YYYY-Wxx-note-draft.md`: 週1のnote要約下書き
- `YYYY-MM-DD-posting-checklist.md`: 投稿前チェックリスト

運用ルール:

- Codexは下書き生成まで。
- X、Threads、noteへの最終投稿は人が確認してから行う。
- 相談導線を入れる投稿は1日1本までにする。
